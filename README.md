# Northstar school management foundation

This project includes a public school website (`school-website.php`), online admissions (`admissions.php`), a protected staff dashboard (`index.php`, with its interface in `dashboard-view.html`), a public family portal (`parent-portal.php`), a PHP/MySQL student register (`students.php`), a protected student details page (`student-details.php`), the dashboard data endpoint (`dashboard-data.php`), and the school records API (`school-api.php`). The public website is the default home page; open `index.php` for the staff dashboard. Students, teachers, classes, enrollments, attendance, payments, timetable lessons, school settings, announcements, achievements, applications, and class learning updates are stored in MySQL.

## Current database coverage

`database/schema.sql` defines tables for students, teachers, classes, enrollments, attendance, payments, timetable, school settings, announcements, achievements, admissions, and learning updates. It preserves existing students and seeds class names from their existing class assignments. Classes have an Active/Inactive setting, and the public pages count only active student, teacher, and class records. `students.php` creates/updates the linked class and current-year enrollment when a student is registered or edited. Staff pages have MySQL-backed add/edit/delete forms. News, achievements, and learning notes have Draft/Published visibility. Admission documents are stored under `private/admissions`, outside direct web access, and can only be downloaded by signed-in staff.

If you already imported the older schema, run `database/upgrade_existing.sql` once, then import the updated `database/schema.sql` in phpMyAdmin. For the public website and admissions module, run or re-run `database/admissions_upgrade.sql`. It safely adds the admission rate-limit table and expands the random application reference field without deleting student or application records. The other migrations create missing tables and add teacher photo and class status fields without deleting student records.

The dashboard uses local student photo paths from `students.photo_path`, limited to files under `images/`. The classroom banner image is a generic, reusable image and is not presented as an individual student's portrait. See `images/ATTRIBUTION.md` for its credit and license.

The public school site displays active teacher records and published achievements/news from MySQL. In the dashboard's Teachers section, choose a photo from the device gallery or file picker; accepted images are saved locally in `images/` and displayed on the public school site. No teacher identities or achievements are fabricated. Families submit applications at `admissions.php`; staff review them at `admissions-admin.php`. Mark an assessment as passed, then select a class and academic year to create the student and active enrollment. Admission documents are limited to PDF/JPG/PNG, three files per application, 2 MB per file, and are downloadable only after staff sign-in. Public applications have a database-backed per-IP rate limit and a longer random confirmation reference.

## Run with XAMPP

1. Copy or place this project folder inside XAMPP's `htdocs` directory.
2. Start Apache and MySQL from the XAMPP Control Panel.
3. For an existing installation, import `database/upgrade_existing.sql` once if you have not already, then import `database/schema.sql`. For a new installation, import only `database/schema.sql`. This creates the `school_management` database and required tables, including the staff account table.
4. Check the MySQL username and password in `config/database.php`. The defaults are the usual local XAMPP values: user `root`, blank password. You can override them with `SCHOOL_DB_HOST`, `SCHOOL_DB_NAME`, `SCHOOL_DB_USER`, and `SCHOOL_DB_PASSWORD` environment variables.
5. From PowerShell in the project folder, create the first staff login with `powershell -ExecutionPolicy Bypass -File .\scripts\create-admin.ps1 -Username admin`. Enter a unique password with 12 to 72 characters at the masked prompt. This setup command only runs in the terminal; it cannot create an account over the web.
6. If you need to change the administrator username or password, run `powershell -ExecutionPolicy Bypass -File .\scripts\change-admin.ps1 -CurrentUsername admin -NewUsername your_new_username` from the project folder. The new password is entered at a masked prompt. Replace `admin` if your current username differs.
7. Visit `http://localhost/school%20project/` for the public website, `http://localhost/school%20project/admissions.php` for applications, or `http://localhost/school%20project/index.php` for the staff login/dashboard.

If you are running PHP's built-in server instead of Apache, open PowerShell in the project folder and run `C:\xampp\php\php.exe -S localhost:8000 -t . router.php`. Keep that terminal open, start MySQL from XAMPP, then visit `http://localhost:8000/` for the public site or `/index.php` for the staff dashboard. Run the SQL in `database/admissions_upgrade.sql` once before using admissions. The router blocks direct web requests to private uploads and internal setup files; without it, PHP's built-in server does not apply the Apache `.htaccess` rules.

The dashboard reads current totals and student records from MySQL. Reports download student, attendance, and payment data as CSV files. School profile settings are saved in MySQL. Staff can publish general school news and class learning updates from the dashboard. Parents can choose a class to see its published notes and timetable subjects; they cannot see a named child's personal records because parent accounts have not been added. The classroom banner is a general reusable photo, not an enrolled student portrait; the attribution is stored in `images/ATTRIBUTION.md`.

Staff pages, student records, and write/read APIs require a staff login. Passwords are stored as hashes; the application uses CSRF checks, prepared database queries, server-side validation, login and application throttling, and security headers. Apache rules block configuration, SQL, hidden runtime-session, and private upload paths; the image directory blocks script execution. The parent portal intentionally remains public and only shows published general announcements, class-level learning updates, and timetable subjects; it does not expose individual student records.

**Deployment status:** this is a local development foundation, not yet an official production-ready service for children's personal data. Authentication currently has one administrator account and no role-based staff access, verified parent accounts, or audit history. Before hosting real records, use HTTPS, set `SCHOOL_ENV=production`, configure the production environment variables (`SCHOOL_DB_HOST`, `SCHOOL_DB_NAME`, `SCHOOL_DB_USER`, `SCHOOL_DB_PASSWORD`, and a unique random `SCHOOL_RATE_LIMIT_KEY`), use a dedicated least-privilege MySQL account, establish secure backups and a data-retention process, and review privacy, hosting, and incident-response requirements for the school's jurisdiction. Set `SCHOOL_FORCE_HTTPS=1` only when the site is served exclusively over HTTPS. If a reverse proxy sits in front of PHP, set `SCHOOL_TRUSTED_PROXY_IPS` to its exact IP address(es) and configure it to overwrite `X-Real-IP`; forwarded IP headers from untrusted clients are ignored. Do not publish real student, family, session, or teacher portrait data in a public repository; `.gitignore` excludes local session files, admission documents, and uploaded teacher portraits. A public GitHub repository contains the application source and schema only, not a secure hosting environment, and should never be used as a database backup.
